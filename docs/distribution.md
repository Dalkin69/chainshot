# Distribution: Scoop and winget

`ChainShot.exe` is a portable program (one zip, no installer), which both Windows package
managers support. Their manifests are generated by the release workflow from the published
SHA-256 (`packaging/update_manifests.py`).

## Scoop

This repository is a Scoop bucket: the release workflow writes `bucket/chainshot.json` and commits
it to `main`.

```powershell
scoop bucket add chainshot https://github.com/Dalkin69/chainshot
scoop install chainshot
```

`scoop update chainshot` installs new versions; `scoop uninstall chainshot` first runs
`ChainShot.exe uninstall --keep-settings` (start with Windows, browser link), and never touches
case folders. The command `chainshot` is added to the PATH and *ChainShot* to the Start menu
(*Scoop Apps* folder).

If the push to `main` is refused (branch protection), the workflow says so; commit `bucket/` and
`packaging/winget/` from the release asset `winget-manifests-<version>.zip` instead.

Once ChainShot is better known, it can be proposed to the official
[Extras bucket](https://github.com/ScoopInstaller/Extras) (it asks for some popularity).

## winget

Package identifier: **`Dalkin69.ChainShot`**. Once accepted in
[microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs):

```powershell
winget install Dalkin69.ChainShot
```

### First submission (once, by hand)

1. Publish the GitHub release; the workflow attaches `winget-manifests-<version>.zip` (three YAML files).
2. On Windows: install [wingetcreate](https://github.com/microsoft/winget-create)
   (`winget install wingetcreate`), extract the zip, then
   `wingetcreate submit --token <GitHub token> <folder>`.
   wingetcreate forks `winget-pkgs` under your account and opens the pull request.
   (Without wingetcreate: fork `microsoft/winget-pkgs` on GitHub, add the three files under
   `manifests/d/Dalkin69/ChainShot/<version>/` and open a pull request.)
3. Microsoft's bots validate the manifests and scan the package; a moderator merges, usually within a
   few days. Answer the bot comments in the pull request if any.

### Later versions (automatic)

Create a GitHub **classic** personal access token with the `public_repo` scope and add it to this
repository as the secret **`WINGET_TOKEN`** (Settings > Secrets and variables > Actions). From then on,
the `winget` job of the release workflow submits each new version by itself. Without the secret the job
only prints a notice.

## Code signing

The executable is not signed yet, so SmartScreen warns on first launch and winget's validation may be
slower. See [code-signing.md](code-signing.md) for the plan (SignPath Foundation).
